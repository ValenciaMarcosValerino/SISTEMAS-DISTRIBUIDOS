===============================================================================
                 GUÍA DE INSTALACIÓN Y EJECUCIÓN — PRACTICA1CHAT
                  Sistemas Distribuidos | Cliente-Servidor TCP
===============================================================================

OBJETIVO
--------
Esta guía permite ejecutar desde cero el proyecto Practica1Chat, disponible en
GitHub. La aplicación es un Messenger de escritorio en Python con interfaz
PySide6, comunicación mediante sockets TCP y almacenamiento de cuentas en
Microsoft SQL Server ejecutado en Docker.

FLUJO DE LA APLICACIÓN
---------------------
1. Se inicia el servidor TCP (server.py).
2. Se inicia la aplicación (login.py).
3. El usuario puede crear una cuenta desde "Crear cuenta" (registro.py).
4. Para iniciar sesión, proporciona su NOMBRE DE USUARIO y contraseña.
5. El servidor consulta SQL Server y verifica la contraseña con Argon2id.
6. Si las credenciales son válidas, se abre Messenger con la identidad de la
   cuenta autenticada. Si son incorrectas, el acceso se rechaza.
7. Dos o más cuentas distintas pueden intercambiar mensajes en el chat general
   y mensajes privados. Una cuenta ya conectada no puede iniciar otra sesión
   simultánea con esa misma identidad.

IMPORTANTE
----------
- La base de datos y las contraseñas de ejemplo NO están incluidas en GitHub.
- Para una primera ejecución, el profesor debe preparar SQL Server y registrar
  una cuenta propia mediante el formulario "Crear cuenta".
- Las contraseñas NO se almacenan en texto plano; se guarda un hash Argon2id.
- La aplicación está configurada PARA PRUEBAS LOCALES en 127.0.0.1.
  No está preparada para publicarse en Internet: el protocolo TCP actual no
  cifra el tráfico. No utilice contraseñas personales o reutilizadas.
- No es necesario ejecutar messenger.py por separado: la aplicación comienza
  en login.py y después abre automáticamente Messenger.

===============================================================================
1. REQUISITOS PREVIOS
===============================================================================

Entorno utilizado durante el desarrollo:
- Windows 11 y PowerShell (terminal de VS Code).
- Python 3.15.x y pip disponibles en la terminal.
- Docker Desktop, configurado para contenedores Linux.
- Microsoft SQL Server 2025, edición Express, en contenedor Docker.
- Microsoft ODBC Driver 18 for SQL Server instalado en Windows.
- VS Code (recomendado), con extensión "SQL Server (mssql)" para consultas.

Bibliotecas Python:
- PySide6          (interfaz gráfica y Qt Designer)
- pyodbc           (conexión con SQL Server)
- argon2-cffi      (hash y verificación de contraseñas)

Comprobar Python y Docker:

    python --version
    python -m pip --version
    docker --version
    docker info

Instalar dependencias Python en el mismo entorno que ejecutará el proyecto:

    python -m pip install PySide6 pyodbc argon2-cffi

Verificar:

    python -c "import PySide6, pyodbc, argon2; print('Dependencias OK')"
    python -c "import pyodbc; print(pyodbc.drivers())"

En la segunda línea debe estar disponible "ODBC Driver 18 for SQL Server".
Si no aparece, instalar el controlador oficial de Microsoft para Windows.

2. OBTENER Y ABRIR EL PROYECTO
===============================================================================

Clonar el repositorio:

    git clone https://github.com/ValenciaMarcosValerino/SISTEMAS-DISTRIBUIDOS.git

Abrir la carpeta clonada en VS Code y localizar la carpeta del chat (si el
repositorio contiene varias prácticas). La terminal DEBE quedar en la carpeta
que contiene server.py, login.py, db.py y messenger.py.

Para localizar el servidor desde la raíz del repositorio:

    Get-ChildItem -Recurse -Filter server.py

Entrar a la carpeta mostrada por el comando anterior. Si Practica1Chat es la
carpeta actual del proyecto, los comandos de ejecución se lanzan desde ahí.

ARCHIVOS PRINCIPALES
--------------------
    server.py                Servidor TCP y administración de sesiones.
    db.py                    Conexión, registro y verificación en SQL Server.
    login.py                 Punto de entrada de la aplicación gráfica.
    registro.py              Registro de cuentas desde la interfaz.
    messenger.py             Ventana del chat y cliente TCP.
    IniciarSecion.ui         Diseño editable del Login (nombre tal como está).
    IniciarSecion_ui.py      Código generado a partir de IniciarSecion.ui.
    Registro.ui              Diseño editable del Registro.
    Registro_ui.py           Código generado a partir de Registro.ui.
    principal_ui.py          Interfaz Python del Messenger.
    principal.ui             Diseño editable del Messenger, si se incluye.
    conectar_ui.py           Formulario de conexión de la etapa anterior,
                            si se conserva en el repositorio.

NOTA: Los archivos *_ui.py se generan con pyside6-uic. No deben editarse
manualmente, porque se sobrescriben al regenerar las interfaces.

===============================================================================
3. PREPARAR SQL SERVER EN DOCKER
===============================================================================

3.1. INICIAR DOCKER DESKTOP

Abrir Docker Desktop y verificar que está funcionando con contenedores Linux.

3.2. CREAR EL CONTENEDOR (SOLAMENTE LA PRIMERA VEZ)

En una terminal PowerShell, descargar la imagen:

    docker pull mcr.microsoft.com/mssql/server:2025-latest

Crear un volumen persistente para conservar los datos:

    docker volume create sql_messenger_data_nuevo

Solicitar una contraseña nueva para el administrador 'sa' (NO se publica):

    $clave = Read-Host "Defina contraseña SQL Server (sa)" -AsSecureString
    $sqlPwd = [System.Net.NetworkCredential]::new("", $clave).Password

La contraseña de sa debe ser FUERTE y cumplir la política de SQL Server.
Utilice al menos 12 caracteres con letras, números y símbolos.

Crear el contenedor:

    docker run -d --name sql-messenger `
      -e "ACCEPT_EULA=Y" `
      -e "MSSQL_SA_PASSWORD=$sqlPwd" `
      -e "MSSQL_PID=Express" `
      -p 127.0.0.1:1433:1433 `
      -v sql_messenger_data_nuevo:/var/opt/mssql `
      mcr.microsoft.com/mssql/server:2025-latest

NOTA: El símbolo ` al final de la línea es la continuación de PowerShell.
Se puede escribir el comando docker run en una sola línea en su lugar.
NO incluir la contraseña ni el contenido de $sqlPwd en el repositorio.

El puerto 1433 corresponde a SQL Server; el puerto 5000 corresponde al chat.

3.3. SI EL CONTENEDOR YA EXISTE

NO repetir 'docker run' ni recrear el volumen. Iniciar el contenedor existente:

    docker start sql-messenger

Comprobar su estado:

    docker ps

Esperar hasta que SQL Server haya terminado de arrancar. Si es necesario:

    docker logs --tail 30 sql-messenger

IMPORTANTE: Si se reutiliza un volumen existente, la contraseña de 'sa' es la
establecida cuando se inicializó ese volumen, NO una contraseña nueva.

===============================================================================
4. CREAR LA BASE DE DATOS Y LA TABLA DE USUARIOS
===============================================================================

En VS Code instalar/abrir la extensión SQL Server (mssql) y conectar con:

    Servidor:                 127.0.0.1
    Puerto:                   1433
    Autenticación:            SQL Login
    Usuario:                  sa
    Contraseña:               la elegida en el paso 3
    Base de datos inicial:    master
    Encrypt:                  Mandatory / Yes
    Trust Server Certificate: Yes (solo entorno local de desarrollo)

Crear una nueva consulta (New Query) y ejecutar el siguiente script.
El script es para una INSTALACIÓN NUEVA. No borra bases de datos existentes.

------------------------ INICIO DEL SCRIPT SQL -------------------------------
IF DB_ID(N'BDD_Messenger') IS NULL
    EXEC(N'CREATE DATABASE BDD_Messenger');
GO

USE BDD_Messenger;
GO

IF OBJECT_ID(N'dbo.Usuarios', N'U') IS NULL
BEGIN
    CREATE TABLE dbo.Usuarios (
        id_usuario INT IDENTITY(1,1) NOT NULL PRIMARY KEY,
        nombre_usuario NVARCHAR(50) NOT NULL UNIQUE,
        fecha_registro DATETIME2 NOT NULL
            CONSTRAINT DF_Usuarios_FechaRegistro DEFAULT SYSDATETIME(),
        id_publico UNIQUEIDENTIFIER NOT NULL
            CONSTRAINT DF_Usuarios_IdPublico DEFAULT NEWID(),
        nombre_mostrar NVARCHAR(50) NULL,
        contrasena_hash NVARCHAR(255) NULL,
        ultima_ip VARCHAR(45) NULL
    );
END;
GO

IF NOT EXISTS (
    SELECT 1 FROM sys.indexes
    WHERE name = N'UX_Usuarios_IdPublico'
      AND object_id = OBJECT_ID(N'dbo.Usuarios')
)
BEGIN
    CREATE UNIQUE INDEX UX_Usuarios_IdPublico
    ON dbo.Usuarios(id_publico);
END;
GO

SELECT TOP (10)
    id_usuario, id_publico, nombre_usuario, nombre_mostrar, fecha_registro
FROM dbo.Usuarios;
GO
------------------------- FIN DEL SCRIPT SQL --------------------------------

La tabla puede estar VACÍA al terminar. Eso es lo esperado: las cuentas se
crean desde la ventana de Registro y quedan almacenadas en el volumen Docker.

DESCRIPCIÓN DE LAS COLUMNAS
---------------------------
- id_usuario:        llave primaria, entero autoincremental.
- id_publico:        GUID único que identifica la cuenta y destinatarios.
- nombre_usuario:    identificador ÚNICO usado para iniciar sesión.
- nombre_mostrar:    nombre visible; se puede repetir entre distintas cuentas.
- contrasena_hash:   hash Argon2id; nunca la contraseña original.
- ultima_ip:        campo disponible para futura información de conexión.
- fecha_registro:    fecha y hora de creación de la cuenta.

Si BDD_Messenger y Usuarios YA existen con el esquema completo, NO es necesario
crear otra base de datos ni volver a añadir columnas.

===============================================================================
5. PREPARAR LA VARIABLE DE ENTORNO DE SQL SERVER
===============================================================================

El archivo db.py lee la contraseña de SQL Server de la variable:

    SQL_MESSENGER_PASSWORD

En la MISMA TERMINAL PowerShell donde se va a ejecutar server.py:

    $clave = Read-Host "Contraseña SQL Server (sa)" -AsSecureString
    $env:SQL_MESSENGER_PASSWORD = [System.Net.NetworkCredential]::new("", $clave).Password

Comprobar que la variable está definida SIN mostrar la contraseña:

    if ($env:SQL_MESSENGER_PASSWORD) { "Contraseña configurada" }

Verificar la conexión Python -> SQL Server:

    python -c "from db import conectar_bd; c = conectar_bd(); print('Conexión exitosa con BDD_Messenger'); c.close()"

IMPORTANTE: Las variables de entorno se configuran POR TERMINAL. Abrir otra
terminal PowerShell NO transfiere automáticamente la variable anterior.
La contraseña solo la necesita la terminal que ejecuta server.py; login.py
NO necesita acceso directo a la base de datos.

===============================================================================
6. EJECUCIÓN COMPLETA DE LA APLICACIÓN
===============================================================================

TERMINAL A — SERVIDOR
---------------------
En la carpeta del proyecto, con SQL Server encendido y la variable configurada:

    python server.py

Salida esperada:

    Escuchando conexiones en: ('127.0.0.1', 5000)

Mantener esta terminal abierta mientras se usa la aplicación.
El servidor no muestra una ventana: permanece a la escucha de conexiones.

TERMINAL B — APLICACIÓN DE ESCRITORIO
------------------------------------
En otra terminal, ubicada en la misma carpeta del proyecto:

    python login.py

Aparecerá la interfaz de inicio de sesión.

SI NO HAY CUENTAS REGISTRADAS
----------------------------
1. Hacer clic en "Crear cuenta".
2. Escribir un nombre de usuario para LOGIN (ej.: alumno01).
3. Escribir el nombre visible (ej.: Alumno).
4. Introducir una contraseña nueva de al menos 8 caracteres.
5. Confirmar la misma contraseña.
6. Hacer clic en "Registrarse".
7. Al confirmar el registro, la aplicación regresa al Login.

PARA INICIAR SESIÓN
-------------------
1. Introducir el nombre de usuario EXACTO elegido al registrarse.
2. Introducir la contraseña de esa cuenta.
3. Hacer clic en el botón Login / Iniciar sesión.
4. Si los datos son correctos, se abre Messenger automáticamente.
5. Si la contraseña es incorrecta, se muestra un aviso y NO se abre el chat.

El nombre de LOGIN puede diferir del nombre visible. Ejemplo:
    nombre_usuario = alumno01
    nombre_mostrar = Alumno

No se inicia sesión escribiendo solamente el nombre visible.

===============================================================================
7. PRUEBA DEL CHAT CON DOS CUENTAS
===============================================================================

1. Dejar ejecutándose UN SOLO server.py en la terminal A.
2. En terminal B, iniciar 'python login.py' y entrar con la cuenta alumno01.
3. Abrir una terminal C, ejecutar de nuevo 'python login.py'.
4. Crear una segunda cuenta si aún no existe, por ejemplo alumno02.
5. Iniciar sesión con la segunda cuenta y su contraseña.
6. Deberán aparecer dos ventanas Messenger, cada una con una cuenta diferente.
7. En "Chat general", escribir un mensaje desde una cuenta y verificar que la
   otra lo recibe.
8. Seleccionar la otra cuenta en la lista lateral y enviar un mensaje privado.
   Debe llegar solamente al destinatario elegido.
9. Cerrar una ventana del chat: la lista de usuarios conectados debe actualizarse.

PRUEBAS ADICIONALES
-------------------
- Contraseña incorrecta: inicio de sesión rechazado.
- Usuario duplicado al registrarse: registro rechazado.
- Dos cuentas distintas con el mismo nombre visible: permitidas, porque sus
  identificadores GUID y nombres de login son diferentes.
- Intentar iniciar la MISMA cuenta desde dos instancias simultáneas: la segunda
  sesión debe ser rechazada.
- Los mensajes privados deben dirigirse a la cuenta elegida, no únicamente
  al nombre visible.

Actualmente el historial del chat se mantiene en memoria del cliente.
No existe todavía persistencia de MENSAJES en SQL Server al cerrar el programa.
La base de datos sí conserva los registros de cuentas y sus hashes.

===============================================================================
8. CONSULTAR LOS USUARIOS REGISTRADOS
===============================================================================

Abrir New Query en SQL Server (mssql), seleccionar BDD_Messenger y ejecutar:

USE BDD_Messenger;
GO
SELECT
    id_usuario,
    id_publico,
    nombre_usuario,
    nombre_mostrar,
    fecha_registro,
    CASE
        WHEN contrasena_hash IS NULL THEN N'Sin contraseña'
        ELSE N'Cuenta con contraseña'
    END AS estado_cuenta
FROM dbo.Usuarios
ORDER BY id_usuario;
GO

Las cuentas antiguas con contrasena_hash = NULL no tienen contraseña registrada
y NO pueden autenticarse mediante el nuevo Login.

IMPORTANTE: no es posible recuperar una contraseña original a partir de
contrasena_hash. Para probar el sistema, crear una cuenta con una contraseña
nueva que se recuerde; preferiblemente guardarla en un gestor de contraseñas.

===============================================================================
9. ACTUALIZAR LOS DISEÑOS DE QT DESIGNER
===============================================================================

Si se modifica un archivo .ui en Qt Designer, los cambios NO aparecen en
Python hasta regenerar el correspondiente *_ui.py.

1. Guardar el diseño en Qt Designer (Ctrl + S).
2. Abrir PowerShell en la carpeta del proyecto.
3. Localizar el ejecutable de pyside6-uic:

    $scripts = python -c "import sysconfig; print(sysconfig.get_path('scripts'))"

4. Regenerar SOLAMENTE el diseño que se modificó:

    & "$scripts\pyside6-uic.exe" IniciarSecion.ui -o IniciarSecion_ui.py
    & "$scripts\pyside6-uic.exe" Registro.ui -o Registro_ui.py
    & "$scripts\pyside6-uic.exe" principal.ui -o principal_ui.py

5. Cerrar la ventana antigua de Python y ejecutar de nuevo 'python login.py'.

No se deben cambiar los objectName de los componentes programados sin modificar
el código Python correspondiente. Por ejemplo, el Login espera:
    txtLoginU, txtLoginP, btnLogin, btnRegistro.

===============================================================================
10. SOLUCIÓN DE PROBLEMAS FRECUENTES
===============================================================================

A. ERROR: "Falta la contraseña de SQL Server"
   - La terminal del servidor no tiene SQL_MESSENGER_PASSWORD.
   - Detener server.py, configurar la variable en ESA terminal y reiniciarlo.

B. ERROR: "No se pudo registrar la cuenta"
   - Revisar el mensaje real en la terminal donde corre server.py.
   - Comprobar Docker, la base BDD_Messenger y la variable de entorno.
   - Comprobar si el nombre de usuario ya está registrado.

C. ERROR: "Usuario o contraseña incorrectos"
   - Usar nombre_usuario, NO nombre_mostrar.
   - Utilizar la contraseña que se escribió al registrarse.
   - Las contraseñas originales no pueden verse en SQL Server.

D. ERROR: "El servidor no devolvió los datos de tu cuenta"
   - Puede haber una versión antigua de server.py ejecutándose.
   - El Login espera login_result con ok=true y un objeto cuenta que contenga
     id_publico, usuario y nombre_visible.
   - Detener instancias antiguas y reiniciar un único servidor actualizado.

E. server.py termina sin imprimir "Escuchando conexiones"
   - Comprobar que el archivo incluye su bloque principal:
       if __name__ == "__main__":
   - Comprobar sintaxis:
       python -m py_compile server.py

F. EL PUERTO 5000 ESTÁ OCUPADO / PROCESOS DUPLICADOS
   - Ver quién escucha:
       Get-NetTCPConnection -LocalPort 5000 -State Listen -ErrorAction SilentlyContinue
   - Ver el proceso asociado:
       Get-NetTCPConnection -LocalPort 5000 -State Listen |
       ForEach-Object {
           Get-CimInstance Win32_Process -Filter "ProcessId = $($_.OwningProcess)" |
           Select-Object ProcessId, CommandLine
       }
   - Si realmente es una instancia antigua de 'python server.py', detenerla:
       Stop-Process -Id NUMERO_PID -Force
   - Sustituir NUMERO_PID por el PID real. No finalizar otros programas.
   - También se puede usar el icono de papelera de la terminal en VS Code.

G. 'pyside6-uic' NO SE RECONOCE EN POWERSHELL
   - Usar su ruta por medio de sysconfig como en el apartado 9.

H. SE GUARDA UN CAMBIO EN DESIGNER PERO NO SE VE EN PYTHON
   - Ejecutar pyside6-uic para actualizar *_ui.py y reiniciar la aplicación.

I. ERROR AL CONECTAR A SQL SERVER EN DOCKER
   - Ejecutar 'docker ps' y comprobar que sql-messenger esté iniciado.
   - Verificar que el puerto 1433 no esté ocupado por otra instalación.
   - Confirmar que se instaló ODBC Driver 18.
   - Verificar contraseña y nombre BDD_Messenger.

J. EL PROFESOR NO VE LOS USUARIOS DE LA COMPUTADORA DEL AUTOR
   - Es normal: GitHub contiene el código, no el volumen de datos de Docker.
   - Preparar SQL Server y crear cuentas nuevas desde Registro.

===============================================================================
11. CÓMO DETENER Y REINICIAR LA APLICACIÓN
===============================================================================

- Cerrar las ventanas Messenger y Login.
- En la terminal de server.py, pulsar Ctrl + C.
- Si Ctrl + C no funciona, utilizar "Kill Terminal" (papelera) de VS Code o
  identificar y finalizar solamente el proceso python server.py como en el
  apartado 10.F.
- SQL Server puede permanecer encendido para las siguientes pruebas.
- Para volver a ejecutar, iniciar el servidor ANTES de abrir 'python login.py'.
- Al abrir una terminal nueva, volver a establecer SQL_MESSENGER_PASSWORD.

===============================================================================
12. OBSERVACIONES TÉCNICAS Y DE SEGURIDAD
===============================================================================

Arquitectura:
    PySide6 Login / Registro / Messenger
           | sockets TCP + JSON delimitado por salto de línea
           v
    server.py (127.0.0.1:5000)
           | pyodbc / ODBC Driver 18
           v
    SQL Server Docker (127.0.0.1:1433)
           | 
           v
    BDD_Messenger.dbo.Usuarios

- La validación de credenciales ocurre en el servidor.
- Argon2id permite verificar contraseñas sin almacenarlas en texto plano.
- id_publico (GUID) diferencia cuentas; la IP no es identidad de usuario.
- El servidor no autoriza mensajes de chat sin autenticación.
- El alcance documentado es local (127.0.0.1). Para uso remoto es necesario
  adaptar host/red y, ANTES de exponerlo, implementar cifrado TLS y otras
  medidas de seguridad de producción.
- No subir contraseñas, archivos .env reales, volúmenes SQL Server, respaldos
  con datos sensibles ni datos de usuarios a GitHub.
